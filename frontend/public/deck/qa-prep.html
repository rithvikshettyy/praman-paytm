RAG in one minute.

RAG answers coverage questions only ("what is the room rent limit in my policy?"). It looks up the policy text first, then writes the answer from that text, with a citation. It never decides a claim.

What is the knowledge base today?

Three layers, all stored in one Chroma index with metadata (layer, insurer, product, doc type, page, source, date, verified_by):

  • Policy documents: one labelled example policy wording so far. Listed in sources.yaml.
  • Regulation: built and tested, but no real circulars loaded yet. The folder only has a README.
  • News: live. Refreshed from allowlisted feeds (see page 2).
The pipeline is real and tested. Policies and circulars are example or still to be loaded; news is live.
Where do the government rules (IRDAI, RBI) actually live?

Two places, on purpose:

  • Rule engine: the numbers it acts on (60-month moratorium, 36-month pre-existing disease cap, room-cap deduction) sit in insurance_health_claim.yaml, each with a source note, all UNVERIFIED for now. The engine does not search text.
  • RAG regulation layer: for quoting the circular itself with a page citation, once the real PDFs are added.

Do not say the knowledge base already holds the circulars. It does not yet.

What is the citation, and who writes it?

The label [Example General Insurance, policy_wording, p.2] is built by our code from the stored metadata of the retrieved chunk. The model only says "S2". It cannot invent a page or a source.

What if the answer is not in the documents?

The answer becomes NO_SOURCE: "I could not find this, so I will not guess." The router then offers a written coverage question to the user's insurer by its legal name. The same happens if the model gives no citation, the retrieval is empty, or the model call fails.

Questions about the RAG.

Likely questions from judges, with a short honest answer for each.

Why RAG and not just ask the model, or fine-tune it?

A policy changes by insurer, product and year. Fine-tuning cannot keep up and cannot cite a page. With RAG the answer comes from the user's own insurer's wording and points to the page, so it can be checked.

The model reads the policy, it does not remember policies.
How do you stop hallucination?
  • The prompt says "use ONLY the numbered sources", temperature 0.
  • Amounts and periods are copied, not calculated.
  • No valid citation means NO_SOURCE.
  • Sentences that promise approval or payment ("will be approved", "guaranteed") are dropped in code.

This lowers the risk. It does not make it zero, which is why every answer carries its page and a "Did this solve it?" Yes/No.

Why only the user's insurer's documents?

Retrieval is filtered to the user's insurer and product, plus regulation. Another insurer's wording is never used. With no insurer and product known, only regulation is searched.

How do you chunk, and why?

PDFs are read page by page (PyMuPDF). Each page is split on clause headings so one clause stays whole. If a page has no headings or a clause is too long, we use 2500-character windows with 300 overlap. Chunk ids are stable (file#p2#c1), and a re-run only re-ingests files whose bytes or metadata changed.

Does RAG decide the claim or change the verdict?

No. RAG never writes to the fact sheet and the engine never imports RAG. A test checks this. Any number RAG surfaces must go through the confidence gate and the user's confirmation before the engine can use it.

RAG explains. The engine decides.
What about documents the user uploads?

In the web chat, an uploaded policy is read in full and held in memory only (up to 5 per case). Smaller chunks (1000 characters), top 10. Answers cite [Your document, file, p.X]. It is dropped on "delete everything" or a server restart. It carries no "not verified" badge because it is the user's own paper, not a legal value of ours.

How does the news layer work?
  • Sources: an allowlist of https feeds only: RBI press releases and notifications (official), Economic Times and Mint (news outlets).
  • What is read: only the title and summary, never the article page.
  • Filter: kept only if it mentions words like insurance, IRDAI, ombudsman, grievance. Items expire after 180 days.
  • Freshness: a background job refreshes every 60 minutes. A re-run adds nothing twice (the id comes from the link). One feed failing does not stop the others.
Near real time, not instant: it checks every hour.
Can news be mistaken for the rule or the policy?

We built against that:

  • News is a separate layer, always UNVERIFIED, cited like [Economic Times, news 2026-10-02, p.1].
  • Any answer citing news ends with a note: it is from a press report, not the policy or the rule, so check the original.
  • The prompt tells the model to say "reported by" and never present news as a policy term.
  • At most 2 news passages per answer, so news cannot push out the user's own policy.
  • News never reaches the rule engine or the verdict.
Why is IRDAI not in the news feeds?

IRDAI publishes no RSS feed (we checked). Its circulars go in as PDFs in the regulation layer instead, listed in sources.yaml with verified_by. RBI has working feeds, so those are the official source for now.

How do you test it?

An eval file with 5 golden questions (one in Marathi, one expected to be NO_SOURCE). Each says what the answer must contain and which page it must cite. All RAG and news tests run offline with hashing embeddings, with Sarvam faked and feeds supplied as plain text.

Be careful: 5 questions is a smoke test, not an accuracy figure. We quote no accuracy percentage.

Why Sarvam?

It covers all 11 languages we ship for chat, reading documents, translation, speech in and speech out with one vendor and one client. For this track the point is Indian languages first.

What does the model NOT do?

It does not do money or date arithmetic, rule checks, or routing. Those are in the pure Python engine and router, with no LLM. Sarvam classifies, reads, translates, speaks, and writes the cited answer.

Where is Sarvam used in the claim check?

Only to read the documents (Doc AI) and to phrase things in the user's language. The deduction itself, such as ₹35,625 on the example bill, is computed by the engine.

Questions about Sarvam.

The engineering choices, and the problems we hit and fixed.

Why sarvam-105b-conversations and not sarvam-105b?

We measured it. sarvam-105b reasoned for 40 to 70 seconds on a long policy and sometimes returned an empty reply when it ran out of tokens. The conversations model answers in about a second. The RAG step also retries once if the reply comes back empty, and falls to NO_SOURCE if it still fails.

Does translation damage numbers and legal terms?

It can, so we protect them. Amounts, percentages, periods, citations and legal names are swapped for placeholders like [[0]] before translating and put back after. If any placeholder is lost or doubled, we show the English answer instead of a wrong one. Citations are removed before translating and added back once each.

Why two translation models?

The formal model inverted who-does-what in everyday Marathi questions. mayura handles colloquial speech better, so questions use it. Answers use the formal model. Whole-page translation also has a small glossary for words the formal model gets wrong (policy, case) and a disk cache.

What data leaves the process?

All text sent to Sarvam passes through redact() first: Aadhaar, PAN, account numbers (9 to 18 digits) and policy or claim numbers are masked. This is applied inside the client, so a new feature cannot skip it.

Limit: a photo sent to Doc AI is an image and cannot be masked. That is why consent is asked, in the user's language, before any document is read.

What happens when Sarvam is slow, rate limited or down?
  • Doc AI has a rate limiter set one below the documented 10 per minute, so bursts queue instead of failing.
  • Calls are clamped to the plan's token ceiling.
  • Translation failure returns the English answer.
  • RAG failure returns NO_SOURCE with the coverage-query handoff.
  • Tests fake Sarvam, so none touches the network.
Does it work without a Sarvam key?

The health check reports 503 until the key is set. For the demo, USE_DOC_FIXTURES=true serves the labelled example policy and bill instead of live Doc AI.

The tricky ones, answered honestly.

Questions that test whether we overclaim. Short true answers win.

"How accurate is it?"

We do not quote an accuracy number. We have 5 golden questions for RAG and 978 backend tests, but no large evaluation on real policies yet. The design limits damage instead: cited answers, NO_SOURCE when unsure, and a person can be asked for.

"Is the regulation content correct?"

Not yet verified, and we say so. Every legal value has verified_by, still UNVERIFIED until a named person checks the source. It shows on screen as a "Not yet verified" badge. verify_report.py lists each one with file and line.

"Is the news reliable? Could it mislead a user?"

News can be wrong or out of date, so it is treated as context only. It is labelled in every answer, marked not verified, capped at 2 passages, and cannot change any number the rule engine uses. Official announcements (RBI) are separated from news outlets in the source list, but nothing is auto-verified.

"Is it real time?"

Near real time. The feeds are checked every 60 minutes and new items are searchable straight away. It is not a live stream, and it only knows what the feeds publish.

"Did you build a chatbot?"

The chat is the front door. Behind it, a rule engine refuses a claim that will be stopped, a router names who owes the answer, and a console counts results from events. RAG is one branch, only for coverage questions.

"Can it say my claim will be approved?"

No. The prompt forbids it, and a code filter drops sentences that promise approval or payment. Nothing is filed either: drafts say "Approved and ready to send".

"What was built in this hackathon versus before?"

Disclosed upfront: the Sarvam client, Doc AI intake, config and translation cache were ported from the earlier Praman repo. Built for this: the claim readiness engine, router, checklist, drafts, console, RAG and the web demo.

"What next?"

Add more official sources, load real policy wordings and regulation into the corpus and verify them by hand, grow the eval set, then the lending ruleset, motor ruleset and deadline reminders.

"You are a distributor: how does Praman help us?"

Cases that belong to the insurer go straight to the insurer, so they never reach the distributor's desk. The console shows "Of N cases, X needed the distributor", counted from events. We invent no savings figure: multiply by your own cost per ticket.
